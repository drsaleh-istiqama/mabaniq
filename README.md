# مبانيك | Mabaniq — الإصدار 0.6.0 (الوحدة ٠ من رفع البنية)
منصة جدوى لإدارة مشاريع التطوير العقاري. الواجهة B (مساحة عمل احترافية).

## التشغيل
```bash
./run.sh          # يثبّت المتطلبات أول مرة ثم يشغّل الخادم
# افتح http://localhost:8800
```
المتطلبات: Python 3.12 وNode 24 (`npm ci && npm run build` مرة قبل التشغيل). البيانات تجريبية (5 مشاريع، 468 وحدة) وتُعاد من زر «إعادة البيانات».

## البنية
- `backend/app.py`: واجهة REST (FastAPI)
- `backend/engines.py`: محركات الذكاء (التسعير، التعثر، السيولة، التحقق من الإنجاز، القرارات، المساعد)
- `backend/seed.py`: بيانات تجريبية حتمية
- `backend/db.py`: SQLite في هذا الإصدار، وPostgreSQL في الإنتاج
- `web/`: مصادر الواجهة (HTML/CSS/JS بلا إطار، ESM) تُبنى بـVite إلى `frontend/dist` (غير مُتتبَّع؛ `npm ci && npm run build`) — ترجمة `web/locales/`، خط Tajawal ذاتي الاستضافة
- `e2e/`: Playwright للمسار الحرج ولمسار استرجاع كلمة المرور (`npm run e2e`)
- `backend/identity.py`: الدخول بالبريد، رابط دخول بريدي، استرجاع كلمة المرور، Google (OIDC) — تظهر بحسب المتغيرات المعيَّنة
- `scripts/backup/`: نسخ `pg_dump` وتمرين استرجاع كامل (`drill.py`) · `load-tests/`: k6 لـ300 مستخدم (`run.sh`) · `db/migrations/`: ترحيلات PostgreSQL مُرقّمة · `db/tests/`: pgTAP
- `tests/`: 84 اختبارًا على SQLite و86 على PostgreSQL (`.venv/bin/python -m pytest -q tests`)

## ما يعمل فعليًا
- صندوق قرارات يولّده النظام من البيانات، والاعتماد يغيّر البيانات ويُسجَّل
- مخطط الأبراج والفلل، وحجز بثلاث خطط دفع تولّد جدول الأقساط، وتأكيد البيع أو إلغاؤه
- تسعير ديناميكي حسب أداء كل شريحة
- العملاء المحتملون: درجة الأولوية، ونقل المراحل، والوحدات المطابقة للميزانية
- رادار سيولة لكل حساب ضمان لـ١٢ شهرًا، مع خطة معالجة
- نموذج التنبؤ بالتعثر مع الأسباب، وإعادة الجدولة
- التحقق من المستخلصات بالأدلة المصوّرة، والاعتماد بالنسبة المتحقق منها
- مساعد يجيب من البيانات الحية مع ذكر المصدر، وبحث وأوامر Ctrl+K، وسجل تدقيق، ووضع فاتح وداكن

## الجديد في 0.5.0 — إغلاق M4 إلى M9 من المراجعة المستقلة (2026-10-09)
- **M4 شرط التبرع:** مبالغ التأخير لم تعد غرامة إيرادية؛ تُقيَّد في دفتر `charity_dues` (مستحق ⟵ محصَّل في أمانة ⟵ مصروف لجهة خيرية)، وتظهر في تصدير ERPNext قيود أمانة لا إيراد؛ البند ٥ من العقد صار شرط تبرع مع بند التزام بالصيغة الشرعية؛ وكلفة التمويل في الجدوى مسمّاة «تمويل إسلامي — مرابحة/إجارة».
- **M5 حماية البيانات الشخصية:** تشفير رقم الهوية وتاريخ الميلاد وهوية المستأجر في القاعدة (Fernet، مفتاح `MABANIQ_PII_KEY` أو `data/secrets/pii.key`)، القوائم تعرض الرقم مخفيًا والاطلاع الكامل يُسجَّل في سجل التدقيق، إشعار خصوصية بإصدار (`/api/privacy/notice`) وموافقة يسجّلها العميل من تطبيقه (أو إقرار ورقي يشهده الموظف) ولا يُصدر العقد قبلها، وسير عمل لطلبات الحذف (`/api/privacy/{id}/process`) يرفض ما دامت التزامات قائمة ويُخفي الهوية دون محو السجل المالي.
- **M6 الأسرار:** سر توقيع بوابة الدفع خارج القاعدة (بيئة أو `data/secrets/`)، لا إقلاع في الإنتاج بلا `MABANIQ_PII_KEY` و`MABANIQ_PAY_SECRET`، ولا حسابات عرض في الإنتاج (مدير واحد بكلمة مؤقتة في ملف يُحذف عند أول تغيير).
- **M7 CSRF/CSP:** رمز CSRF مزدوج (كوكي `mbq_csrf` + ترويسة `X-CSRF-Token`) على كل طلب مُعدِّل، وسياسة محتوى بلا `unsafe-inline` للسكربتات: نُقلت كل السكربتات المضمّنة إلى `/static/*.js` وأُزيلت معالجات `onclick` الستون لصالح تفويض `data-call`.
- **M8 السوق الثانوي:** قبول العرض يفتح تسوية مالية صريحة (`resale_settlements`: مستحق للبائع = سعر التنازل − الأقساط المتبقية)، والعقد يصير `assigned_pending_kyc`، ولا تسليم قبل توثيق هوية المشتري وتوقيع الملحق، وحساب دخول للمشتري عبر `/api/customers/{id}/account`.
- **M9 التأجير:** الدفعة الأخيرة بنسبة ما تبقى من المدة (١٣ شهرًا ربع سنوي = ٤×١٬٥٠٠ + ٥٠٠).
- اعتماد جديد: `cryptography`. انظر `CHANGELOG-0.5.0.md`.

## الجديد في 0.4.1 — إصلاحات المراجعة المستقلة (2026-10-09)
- **M1** الفواتير تُربط بمعرّف العميل (`invoices.customer_id`) لا باسمه؛ بوابة العميل لا تعرض إلا فواتيره (كان عميلان بالاسم نفسه يريان فواتير بعضهما).
- **M2** لا تسليم مع قسط تمويل بنكي غير مسدَّد إلا بخطاب صرف بنكي مرفق على الحجز (مستند بالفئة «خطاب صرف بنكي»)؛ ويُذكر المستند في سجل التدقيق.
- **M3** العربون عند تأكيد البيع يمر بمسار السداد الموحّد (دفتر المدفوعات + إيصال + فاتورة)، والبذور تُكمل أي فارق تاريخي؛ `/api/bank` يعرض `ledger_gap` ويجب أن يكون صفرًا.
- ترحيل تلقائي للقواعد القائمة (عمود `customer_id`)؛ فواتير أُصدرت قبل 0.4.1 بلا معرّف لن تظهر في بوابة العميل حتى تُربط يدويًا. راجع `CHANGELOG-0.4.1.md`.
