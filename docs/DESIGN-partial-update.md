# التحديث الجزئي بدلالة PATCH صريحة — جرد وتصميم (0.30.0)

**الدافع.** تقييم شركة المخطط العقارية للمنصة: في تحديث الترخيص يبقى الرقم المرجعي وتاريخ الانتهاء بقيمتهما القديمة إن أُرسلا فارغين، والواجهة
تعلن «حُدّث الترخيص» بعد أي حفظ ولو لم يتغير شيء. تحقّقنا من الأمثلة في الكود فصحّت (`backend/modules.py` السطر 123)، ثم فحصنا كل تحديث في
الخادم بالنمط نفسه وبأنماطه المكافئة في بايثون. هذه الوثيقة جردٌ بالنتيجة وتصميم للإصلاح.

## 1. الدلالة المعتمدة

| ما يصل من العميل                          | الأثر                                                                                              |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- |
| حقل غير مُرسَل (ليس في `model_fields_set`) | **لا يُمس** — ولا يعني «فارغ» أنه «لا تغيير»                                                        |
| حقل اختياري مُرسَل `null` أو `""` أو مسافات | **يُفرَّغ** (NULL)                                                                                 |
| حقل إلزامي مُرسَل فارغًا أو null          | **يُرفض** بـ400 ورسالة عربية تسمّي الحقل: «الحالة» حقل إلزامي ولا يُفرَّغ                          |
| حقل مُرسَل بقيمته الحالية                  | ليس تغييرًا                                                                                        |
| لم يتغيّر شيء                             | لا `UPDATE` ولا سطر تدقيق ولا `commit`، والرد `changed: []`                                         |

الرد من كل نقطة معدَّلة: `{ok, changed: [أسماء الحقول], changes: [{field, label, old, new}]}`. بقيت `changed` قائمة أسماء نصية كما في نقاط الموارد
البشرية القائمة واختباراتها؛ والتفاصيل في `changes`. سطر التدقيق عند التغيير: «الحقل: «القديم» ⟵ «الجديد»». **البيانات الشخصية والمشفّرة
(الاسم والهاتف والبريد والهوية والآيبان والعنوان والملاحظات الحرة) تُذكر بالاسم وحده**: لا قيمة قديمة ولا جديدة في التدقيق ولا في الرد.

## 3. التصميم

ملف واحد: `backend/partial.py`.

```
Col(label, required=False, personal=False, secret=False, kind="text|num|date|bool", check=None, to_db=None)
plan(cur, body, spec, extra=None) -> Patch        # نقية: لا كتابة. ترفض تفريغ الإلزامي وما يرفضه check
Patch.changed / .changes / .value(field) / .detail() / .response(**extra)
Patch.commit(c, table, id, action, subject)       # UPDATE + سطر تدقيق + commit — فقط إن تغيّر شيء
partial_update(...)                               # plan + commit للحالة البسيطة
```

- **`spec`** يعدّد الأعمدة القابلة للتعديل: اسمها العربي، وهل هي إلزامية، وهل شخصية/مشفّرة، ونوعها للمقارنة (`num` يعدّ 5 و5.0 متساويين؛ `date` يقارن أول عشرة
  أحرف؛ `bool` يعدّ NULL صفرًا).
- **المشفّر** (`secret`): تُقارَن القيمة المفتوحة (`pii.dec`) لأن النص المشفّر يتغير في كل تشفير، وتُكتب مشفّرة، ولا تُعاد ولا تُدقَّق.
- **`extra`**: قيم يشتقها الخادم نفسه (تاريخ الصدور عند الانتقال إلى «صادر»، المالك الافتراضي عند الدخول في محفظة التأجير)؛ تُقارَن وتظهر في
  `changes` باسمها العربي كما تظهر أي قيمة.
- **قواعد عمل النقطة** (مالك موجود؟ وحدة عليها عقد؟) تقع بين `plan()` و`commit()` وتقرأ `p.value("status")`، فلا تُنفَّذ كتابة قبل اكتمال الفحوص
  (درس 0.19.1: رفض بعد `INSERT` يُبقي قفل الكتابة في SQLite).
- **نماذج PATCH متساهلة في الأنواع**: كل حقل `Optional` بلا `min_length` ولا `pattern`، لأن 422 العام يصل للمستخدم «تعذّر تنفيذ الطلب»؛ الحدود
  الدنيا والأنماط في `Col.check` برسالة عربية. النماذج الجديدة `extra="forbid"` كي لا يُبتلع حقل مكتوب خطأً بصمت.
- **الأفعال**: المسارات القائمة بـ`POST` تبقى (توافق)، وتُسجَّل معها `PATCH` على الدالة نفسها.

## 4. الواجهة

- `patchMsg(r)`: «لم يتغيّر شيء» إن كانت `changed` فارغة، وإلا «حُدّث: <أسماء الحقول بالعربية>» من `changes[].label`.
- كل حقل تاريخ اختياري في شاشات التعديل يجاوره زر **«مسح»** (`data-call="clearField"`) — حقل التاريخ الأصلي لا يُمسح في سفاري على الجوال.
- نموذج الترخيص يحدّد الحالة الحالية، ويرسل ما تغيّر وحده؛ وقائمة المالك في الوحدة تحمل «بلا مالك».
- الحقول المقنَّعة (هوية المالك وآيبانه): لا تُرسَل ما لم يكتب المستخدم قيمة جديدة أو يضغط «مسح القيمة المحفوظة».

## 5. الاختبارات (SQLite وPostgreSQL)

`tests/test_partial_update.py`: وحدة نقية للدالة (التطبيع، الإلزامي، المشفّر، المقارنة) · الترخيص (تفريغ الاختياري، رفض الإلزامي، الإرسال نفسه
`changed: []` بلا سطر تدقيق، غير المُرسَل لا يُمس، تاريخ الصدور لا يتحرك) · الوحدة (مالك/مواقف) · المخطط · المالك (مشفّر لا يُعاد، لا يُدقَّق) ·
المستأجر · الحساب · المورّد · البريد (التوثيق يبقى) · e2e للترخيص من الواجهة.

## 6. قرارات منفّذة بلا رجوع للمالك (قابلة للمراجعة)

1. `changed` بقيت قائمة أسماء (توافق مع الموارد البشرية واختباراتها) و`changes` تحمل التفاصيل.
2. هوية المالك وآيبانه صار «فارغ مُرسَل» يعني **مسح** (كان «أبقِ» بقرار 0.29.2)؛ ولا تُرسله الواجهة إلا بقصد. تعديل قرار 0.29.2 موثَّق هنا.
3. إعادة حفظ بريد المستخدم نفسه لم تعد تُسقط توثيقه.
4. تاريخ الصدور يُحدَّد عند **الانتقال** إلى «صادر» فقط؛ وتاريخ التقديم عند أول انتقال إن كان فارغًا.
